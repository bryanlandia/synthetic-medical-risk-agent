## Context

See proposal.md for motivation. This is a text-and-framing change. Today the About text is `web/content/about.md`, rendered by the About tab; the page header lives in `web/components/Demo.tsx`; the page `<body>` is in `web/app/layout.tsx`. The model card is generated by `training/src/training/model_card.py` into `training/model/MODEL_CARD.md` and copied to `web/content/model-card.md` by `training card`. The model hash covers only `reader.json` and `classifier.json`, so card text does not move it.

## Goals / Non-Goals

**Goals:** one consistent fictional story (disease course, pathway, two ledgers, funder) in the About tab, footer, model card and README, with the known About inaccuracies fixed.

**Non-Goals:** any scoring, UI feature or eval change; retitling the page; real clinical claims; measured or illustrative savings figures; describing features that do not exist yet as live.

## Decisions

- **Footer in the layout, not per tab.** A footer in `layout.tsx` is on every screen by construction, so the "every tab" requirement cannot be missed by a new tab. Alternative: add it to each tab component, which would drift.
- **Card text goes into the generator.** The card is regenerated, and tests fail on a stale or hand-edited card, so the added text is a string in `model_card.py`. Alternative: edit the markdown, which the next `training card` would overwrite.
- **The page title and header subtitle stay.** The existing requirement that every screen states the disease is fictional, and tests that match the header text, are left as they are. The story lives in About and the footer.
- **Future features are written as "next", not "live".** The About TODO list becomes a short "what comes next" that names the evidence-first chart and the scan-readiness packet only as planned, so the text is true on the day it ships.
- **Funder stays out of the data path.** It appears only in static text. No request, prompt or report mentions it, so evals and the agent's behaviour are unchanged.

## Risks / Trade-offs

- [The story overclaims "highly treatable" and reads as clinical] → keep it one fictional sentence, no treatment or outcome numbers, and test the text for those.
- [Playwright tests assert About headings from the file] → they read the file, so new headings pass; the footer is covered by a new test.
- [The card test or `web/content/model-card.md` goes stale] → regenerate with `training card` and run the training card tests.
- [About text states a result that later changes] → keep the Haiku AUC (0.735) next to its source split so it is easy to re-check.

## Migration Plan

Text and one component change, shipped with the normal Vercel deploy of the web project. Rollback is a revert. No data, model or service change.
